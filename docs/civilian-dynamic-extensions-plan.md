# Civilian dynamic relief extensions — implementation plan

## Authorization and design
Implement the previously offered civilian extensions autonomously, as explicitly requested. Preserve the existing military exclusions. This increment adds source-driven civilian replanning, configurable bounded fictional fixtures, deterministic specialist communication and a public weather integration. Choices here are implementation decisions; they are not claims that the user supplied all these details.

Node/Express/SQLite/Kafka remain the existing stack. No new runtime dependency. Only ordinary civilian facts for a named fictional run affect the educational exact one-wave optimizer. Resource bounds remain three aircraft, three crews, three airports, two routes and five ordinary cargo requests. Preserve strict schemas, independent plan verification, atomic rollback, source/admin/viewer separation and exact replay. No weapons, adversary assessment or military retasking.

## Contracts
Start accepts existing fields plus optional `inputMode` (`scripted` default or `gateway`) and optional `configuration`. Custom configuration requires gateway mode. Configuration contains strict aircraft/crews/airports/weather/routes/requests collections, optionally demandHistory, using existing entity shapes. Server owns run UUID, creation time, logical tick, revision, fixed policy and solver budget. SIM identifiers total at most20 characters, references resolve, and qualification identifiers begin with a lowercase letter. Wholly empty worlds are rejected. Cargo priority/coldStorage metadata remains configuration-owned. No arbitrary objectives, tools, provider URLs or real fleet identifiers.

Gateway snapshots add `inputs:{mode,namespace:'input-<UUID>-',authorities:{eventType:sourceId},bindings:[]}`. The first configured source permitted for a type becomes its authority when the run starts; persist this choice. Only exact namespaced known entities from that authority may affect the run via existing POST /v1/events or /batch. Unbound or nonauthoritative facts still enter ordinary history. Mirrored output uses a separate `relief-<UUID>-` namespace, avoiding feedback. Persist validated input receipts, apply only nonduplicate current events, solve/check, and persist mirrors + world in one synchronous SQLite transaction. Any incompatibility/solver/outbox/state failure rolls back the entire batch. One effective batch produces one revision. Stale, expired, duplicate and unbound events do not produce revisions.

Mapping preserves configuration-only priority/coldStorage. Aircraft/cargo airport references resolve inside input namespace. Airport hourly capacities must be even0..6 and map /2 to toy slots. Crew duty and cargo deadline timestamps align to fixed30-minute slots relative to createdAt, within existing slot bounds. Crew qualification grammar matches both planner and canonical gateway. Weather preserves temperature/wind/visibility/condition. No unknown entity creation.

Bindings record type/entityId/scenarioEntityId/eventId/sourceId/observedAt/validUntil/expired plus optional maintenanceDueAt/expiryReason. Maintenance is checked against receipt time; a future due time caps an available aircraft's effective binding validity. Input wall-clock TTL is independent of logical tick. Timer expiry invalidates bound resources and recomputes a verified plan atomically. Read snapshots derive `inputFreshness:{status,expiredCount,replanPending}` and `planUsable`; overdue pending bindings make prior plans historical even if expiry commits fail. Restart expires due input and marks interrupted pending weather as degraded. Accepted updates at current revisions0..18 can produce revision19; new bound updates at19 are refused. Final expiry at20 conservatively ends all remaining bound resource validity and requires a new run. Ordinary unbound ingestion remains available.

Mirrors inherit current bound TTL and maintenance evidence. Expired bindings are omitted; their prior mirrored facts expire naturally rather than being emitted as newly fresh. Slot timestamps stay anchored at run creation. Expiry may emit zero mirrors and must still persist a verified empty proposal. Mirrored facts are simulation-derived outputs, not new independent physical sensor readings.

`coordination:{version:1,topology:'specialists-supervisor',messages:[{id,from,to,kind,entityIds,findingIds,summary}],decision:{status:'verified',servedPriority,assignedCount}}` is a deterministic trace. Referenced findings belong to current plan.agentReports. No autonomous LLM negotiation, tool execution or LLM authority over feasibility. Existing optional multi-model local annotations continue selecting known evidence only.

Admin-only POST /v1/simulation/weather accepts strict UUID commandId/runId, expectedRevision0..18, existing SIM airportId and location delhi/mumbai/chennai. Fixed HTTPS Open-Meteo provider, fixed civilian city coordinates, redirect rejection, timeouts, bounded response, strict UTC units/time/numerical checks. Current model estimates + nearest-hour visibility retain distinct sample timestamps; missing visibility fails explicitly. Network is outside DB transactions. Recheck run/revision after fetch, discard superseded results, single flight, abort/drain on close. Successful canonical input uses the ordinary transactional path. Provider failure persists explicit degraded status with no invented data or revision. Exact command receipts retain success/degradation and finalization errors after network execution. Capacity failures before fetching do not retain a command. No automatic third-party polling; explicit live refresh only. WeatherFeed snapshot shape status/runId/revision/commandId/airportId/location/generatedAt plus provenance/errorCode/eventId as applicable. Viewer shows timestamps and earlier-revision warning.

## Review rulings
Leading-hyphen crew qualifications and wholly empty configurations fail at schema boundary. WMO97 is a supported heavy-thunderstorm category. Aircraft due dates use receipt time and future validity caps. Mirrors preserve input TTL, temperature and fixed slot anchoring. Weather finalization failures retain exact error receipts. Task reviews independently reproduced these cases before regression fixes.
